관리자 매뉴얼

회원 관리 · 자료 등록 · 자료 관리 · 로그인 이력

1. 관리자 화면

관리자 계정으로 로그인하면 상단 메뉴에 관리자 메뉴가 표시됩니다. 관리자 화면에서는 회원과 자료를 관리할 수 있습니다.

회원 관리 — 회원 등록, 회원 정보 수정, 권한 및 상태 관리
자료 관리 — 자료 등록, 검색, 수정, 공개/비공개, 원본 확인, 삭제
로그인 이력 — 누가 언제 로그인했는지 확인

2. 회원 관리

회원 등록

관리자 → 회원 관리에서 새 회원을 등록합니다.

항목입력 내용
이름회원의 이름
아이디로그인에 사용할 아이디
이메일회원 이메일
소속 지부회원이 소속된 지부
권한일반회원 또는 관리자
초기 비밀번호회원에게 전달할 최초 비밀번호
첫 로그인 후 회원이 자신의 비밀번호를 변경할 수 있도록 안내합니다.

회원 목록

회원 목록에서 이름·아이디·이메일을 검색하고 상태, 권한, 지부별로 필터링할 수 있습니다.

회원 정보 수정 — 이름, 아이디, 이메일, 지부, 권한, 상태를 수정합니다.
비활성화 — 해당 계정의 로그인을 제한할 때 사용합니다.
활성화 — 비활성 계정을 다시 사용할 수 있도록 합니다.
관리자 권한은 꼭 필요한 사람에게만 부여합니다.

3. 자료 등록

관리자 → 자료 관리 → 자료 등록에서 진행합니다.

① 제목을 입력합니다.
② 자료에 대한 간단한 설명을 입력합니다.
③ 카테고리를 선택합니다.
④ 언어, 저자, 작성연도를 입력합니다.
⑤ 파일을 선택합니다.
⑥ Drive에 저장하고 등록을 선택합니다.

파일은 Google Drive에 원본으로 저장되고, 자료 정보는 아카이브에 등록됩니다.

파일 형식은 선택한 파일에서 자동으로 인식됩니다. 업로드 중에는 페이지를 닫거나 새로고침하지 않는 것이 좋습니다.

4. 자료 관리

등록 자료 관리에서는 제목·저자·파일명 검색, 분야 및 공개 상태 필터, 정렬 기능을 사용할 수 있습니다.

수정 — 제목, 설명, 카테고리, 언어, 저자, 작성연도, 파일 형식, 공개 상태를 수정합니다.
원본 — Google Drive에 저장된 원본 파일을 확인합니다.
삭제 — 자료를 삭제합니다. 현재 시스템에서는 삭제 시 Google Drive 원본도 휴지통으로 이동합니다.
삭제는 실제 원본 파일에도 영향을 주므로 삭제 전 제목과 파일을 반드시 확인합니다.

5. 공개 / 비공개 관리

자료를 내부적으로만 보관해야 하는 경우 자료 수정 화면에서 공개 상태를 비공개로 변경합니다.

공개 — 일반 회원이 자료실에서 검색하고 열람할 수 있습니다.
비공개 — 일반 자료실에서 공개되지 않도록 관리합니다.

6. 로그인 이력

관리자 → 로그인 이력에서 최근 로그인 기록을 확인할 수 있습니다.

기록에는 로그인 시간, 이름, 아이디, 권한, 소속 지부가 표시됩니다.

정기적으로 확인하여 계정 사용 현황과 이상 로그인 여부를 점검합니다.

7. 관리자 계정 보안

관리자 아이디와 비밀번호를 여러 사람과 공유하지 않습니다.
관리자 권한이 필요하지 않은 계정에는 관리자 권한을 부여하지 않습니다.
사용하지 않는 계정은 비활성화합니다.
자료 삭제 전 Google Drive 원본을 반드시 확인합니다.

8. 개발자용 부록

개발자가 시스템을 유지·보수할 때 확인해야 할 구조입니다.

주요 구성

구성역할
index.html로그인, 회원 화면, 자료실, 관리자 화면의 프론트엔드
worker.js인증, Google Sheets/Drive 연동, 자료·회원 API
api/Vercel API 라우팅 관련 구성
_redirects라우팅 보조 설정

Google Sheets / Drive

회원·자료·댓글·로그인 이력 등의 데이터는 Google Sheets를 기반으로 관리하며, 원본 파일은 Google Drive에 저장합니다. Worker는 서비스 계정 인증을 통해 Sheets와 Drive API를 사용합니다.

주요 환경 변수는 GMC_SHEET_ID, GMC_ROOT_FOLDER_ID, GMC_SA_EMAIL, GMC_SA_PRIVATE_KEY, GMC_SESSION_SECRET 등입니다.

배포

사이트는 Vercel 배포를 기준으로 운영합니다. 개발 중에는 불필요한 Production Deploy를 반복하지 않고 변경사항을 충분히 확인한 뒤 배포합니다.

개발자 매뉴얼의 상세 내용은 시스템 변경 시 실제 코드와 환경변수 구성을 기준으로 갱신합니다.
